# 桌面标零与采集诊断

`config/calibration_pose.json` 的参考关节角约为 `[0, 100.15404, 8.86976, 0]` 度。
它是人工支撑的桌面姿态，不是 URDF 数学零位，也不是自动运动目标。
配置仍标为未完成现场几何验证，照片不能替代安装方向和几何确认。

每轴在这个姿态采集 SDK 的转子角 `q_rotor_ref`，与参考关节角 `q_joint_ref` 配对。
`direction` 为安装方向 ±1，`r` 为减速比（GO-M8010-6 配置为 6.33）：

```text
q_joint = q_joint_ref + direction * (q_rotor - q_rotor_ref) / r
q_rotor = q_rotor_ref + direction * r * (q_joint - q_joint_ref)
rotor_zero = q_rotor_ref - direction * r * q_joint_ref
```

旧版硬件候选计算 `rotor_zero` 时漏乘 `r`，提交后的第一帧反馈会把参考关节角缩小
6.33 倍。修复后的界面显示“标零映射 v2”，并展示桌面参考角、采集转子角和当前关节角。
旧进程不会热加载代码；确认外部支撑及安全停机后再重启应用、重新采集和提交，不能复用旧候选。
标定当前只保存在进程内存中，不会修改现场 YAML/JSON 编码器标定文件。

## `capture_unstable`

该拒绝发生在候选生成前，不是桌面参考角的软限位检查。诊断保存在快照
`capture_diagnostic`，也持续显示在 Viser 标零面板，包含采样编号、motor ID 和触发原因。

| 原因 | 拒绝条件 |
|---|---|
| `motor_ids` | 返回 ID 或顺序与配置不符 |
| `motor_error` | 电机返回 `merror != 0` |
| `mode` | 实际返回模式不等于 SDK 的 BRAKE 模式 |
| `velocity` | 任一帧转子速度绝对值超过 0.02 rad/s |
| `temperature` | 温度超过 60 °C |
| `position_span` | 采集窗口内转子位置极差超过 0.02 rad |
| `non_finite` | 位置、速度、力矩或温度不是有限数值 |

速度门限是转子侧数值，除以 6.33 后约为关节侧 0.181°/s。需要看到具体实测值才能
区分真实运动、速度估计噪声或其他异常；不要仅为了通过采集删除检查或放宽门限。
超时或 CRC 错误由总线层另行拒绝。稳定采集至少 200 帧，失败不生成新候选。

桌面姿态的 J2 在硬限位内、正常软限位外，正确完成标零后仍应禁止直接使能正常运动。
BRAKE 查询本身会发送状态切换指令，并非被动读取，也不提供机械抱闸。
软件关闭和进程退出不能保证电机已撤销最后输出，机械支撑和物理断电手段必须保留。
